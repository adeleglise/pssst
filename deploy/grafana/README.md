# Grafana dashboard

Both files here are generated by `build_dashboard.py`, never hand-edited, and
CI fails when either differs from what the script produces. Regenerate them
after any change:

```sh
make dashboards
```

| File | Format | Language | For |
| --- | --- | --- | --- |
| `pssst-v2.json` | Schema v2, tabbed layout | French | Grafana 12+ with `dashboardNewLayouts`, published through the v2 API. |
| `pssst-grafana-com.json` | Classic JSON model, rows | English | Grafana 10+, imported from a file or from grafana.com. Asks for the Prometheus datasource at import. |

The classic file is the same dashboard: each tab's rows become rows of panels,
the first tab's open and the others collapsed. Every French string has its
English entry in `EN` in the script, and a missing one fails the build.

## Import the classic dashboard

Dashboards → New → Import, then upload `pssst-grafana-com.json` and pick the
Prometheus that scrapes PSSST and loads its rules. Without the rules in
`deploy/prometheus/pssst.yml`, the headline panels stay empty: the correlation
lives in Prometheus, not in the exporter.

## Publish the v2 dashboard

```sh
curl -X POST -H 'Content-Type: application/json' --data-binary @pssst-v2.json \
  http://GRAFANA/apis/dashboard.grafana.app/v2beta1/namespaces/default/dashboards
```

## List it on grafana.com

Sign in at grafana.com, open My Account → Dashboards → Upload, and upload
`pssst-grafana-com.json`. Use `brand/png/icon-256.png` as its logo and a
screenshot of the overview rows. Upload a new revision after every change to
the generator; the listing does not follow the repository.

## What it shows

The first rows answer the two questions worth asking at a glance: who is down,
and who is in planned maintenance. The others are for looking closer: declared
status, observed probes, and collection health, which is where the cumulative
counters show whether a gap is the provider failing or us failing to measure
it.
