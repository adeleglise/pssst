# PSSST Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for isolated adapter and delivery tasks, with runtime integration performed in this session.

**Goal:** Implement and verify the complete Go exporter MVP from the supplied specification.

**Architecture:** Independent status and probe workers publish last-known-good snapshots into a bounded cache. A custom collector serves cached signals; Prometheus rules perform correlation.

**Tech Stack:** Go 1.27, net/http, slog, prometheus/client_golang, prometheus/common/expfmt, go.yaml.in/yaml/v3; Podman Compose and promtool.

**Spec:** `docs/superpowers/specs/2026-09-18-pssst-design.md` and `docs/specification.md`.

## Global constraints

- No PSP requests inside scrapes; preserve separate signals and last-known-good snapshots.
- No credentials/URLs/free-form remote text in labels or logs.
- Cap PSPs 128, probes per PSP 32, component mappings 128, upstream entities 1024, HTTP bodies 2 MiB, config 1 MiB.
- Strict cancellation/timeouts, fixed worker inventory, strict YAML, deterministic local tests.
- No real PSP production endpoints in automated tests.
- Use Podman locally; prepare integration for the existing NAS Prometheus/Grafana without deploying remote changes.
- User authorizes implementation without additional approval. Empty repository has no reusable baseline; use a feature branch in place.
